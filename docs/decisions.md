# 결정 기록 (ADR)

새 결정은 아래에 번호를 이어서 추가한다. 이미 내린 결정을 뒤집을 때도 기존 항목을 고치지 않고 새 ADR을 쓴다.

## ADR-0001 — 처음부터 다시 시작 (2026-10-03)
- **결정:** 기존 SvelteKit + Hono/Workers 모노레포를 모두 지우고 Astro 단일 앱으로 새로 시작한다.
- **이유:** 소유자의 지시다. 목표는 Adwaita 디자인, 아주 빠른 로딩, 단순한 기능 구성이다.
- **유지하는 것:** git 히스토리만 남기고, 코드와 문서는 이어받지 않는다.

## ADR-0002 — Astro 7 정적 출력과 Vercel
- **결정:** `output: "static"`으로 빌드한다. 서버에서 실행되는 경로는 `/api/geo` 하나뿐이다(`prerender = false`).
- **어댑터 설정:** `@astrojs/vercel` 11을 쓴다.
  - `imageService: false`로 런타임 이미지 변환 비용을 없앤다.
  - `staticHeaders: true`로 CSP를 HTTP 헤더로 보낸다.
- **리전:** 어댑터에는 리전 옵션이 없으므로 `vercel.json`의 `regions: ["icn1"]`로 지정한다.

## ADR-0003 — 데이터는 git에 커밋된 JSON, 갱신은 GitHub Actions
- **결정:** `scripts/sync/`가 공식 소스에서 데이터를 가져와 `src/data/**`에 JSON으로 저장한다.
  - `.github/workflows/sync.yml`이 6시간마다(미러는 매일) 실행한다.
  - 데이터가 바뀌었을 때만 커밋하고, Vercel이 자동으로 재배포한다.
- **이유:**
  - 페이지가 완전히 정적이라 가장 빠르다.
  - 변경 이력과 롤백을 git으로 관리할 수 있다.
  - 런타임 데이터베이스나 KV가 필요 없다.
- **실패 처리:** 어댑터 하나가 실패하면 그 배포판만 마지막 정상 데이터를 유지한다. 3번 연속 실패하면 이슈를 연다.

## ADR-0004 — 미러 추천 방식
- **결정:** `/api/geo`가 Vercel의 `geolocation()`으로 국가와 좌표를 알려 주면, 브라우저가 정적 미러 JSON을 받아 순위를 매긴다.
  - **정렬 기준:** 같은 국가 → 하버사인 거리(미러 좌표가 없으면 국가 중심 좌표) → HTTPS → 공식 점수
  - **대체 경로:** 실패하면 브라우저 시간대에서 위치를 추정한다(IANA zone1970 좌표). 그것도 안 되면 공식 기본 CDN을 쓴다.
- **공식 리다이렉터가 있는 배포판:** Fedora, openSUSE, Kali처럼 공식 리다이렉터·CDN이 있으면 그것을 기본으로 고르고, 화면에 "자동으로 가까운 서버"라고 표시한다.
- **개인정보:** 위치 정보는 `no-store`로 응답하고 기록하지 않는다. 브라우저 Geolocation API는 쓰지 않는다.

## ADR-0005 — 다국어: 한국어 기본, 영어 `/en/`
- **결정:** 모든 페이지를 `src/pages/[...locale]/` 아래 하나의 파일로 두 언어용으로 생성한다.
- **자동 리다이렉트 없음:** 언어를 자동으로 바꾸지 않는다. hreflang과 언어 전환 버튼만 둔다(SEO 친화적이고 서버 비용이 없다).
- **UI 문자열:** `src/i18n/{ko,en}.ts`에 둔다.

## ADR-0006 — Adwaita 디자인 토큰
- **결정:** libadwaita 1.10의 `_colors.scss` 값을 CSS 변수로 그대로 옮긴다. 모서리 반경도 libadwaita를 따른다(버튼 9px, 카드 12px, 다이얼로그 15px).
- **폰트:**
  - Adwaita Sans/Mono 51.0(OFL)의 라틴 subset을 woff2로 직접 호스팅한다.
  - 한글은 시스템 폰트를 쓴다. 웹폰트 0바이트로 Lighthouse 100을 노린다.
- **아이콘:** Adwaita symbolic 아이콘(CC BY-SA 3.0)을 쓴다.

## ADR-0007 — CSP와 클라이언트 JS 규칙
- **결정:** Astro `security.csp`로 inline script와 style의 해시를 자동으로 넣는다.
  - Pagefind 때문에 `'wasm-unsafe-eval'`을 허용한다.
  - 코드 하이라이트는 Prism을 쓴다. Shiki는 inline style을 써서 CSP와 맞지 않는다.
  - 페이지 전환은 CSS `@view-transition`으로 하고 ClientRouter는 쓰지 않는다.
- **meta CSP의 한계:** `frame-ancestors`는 meta 태그로 보낼 수 없으므로 `vercel.json`의 `X-Frame-Options: DENY`로 대신한다.

## ADR-0008 — 배포판 목록은 편집자가 정한다
- **결정:** DistroWatch를 크롤링하지 않는다(robots.txt가 AI 봇을 금지한다). 수록 목록(약 50개)은 편집자가 정한다.
- **정렬:** 인기 순위를 다른 사이트에서 가져와 표시하지 않는다. 정렬은 추천순(편집), 이름순, 최근 업데이트순만 둔다.

## ADR-0009 — 접근성을 위해 libadwaita 값을 일부 바꾼다
- **결정:** libadwaita 토큰을 그대로 쓰되, WCAG 2.2 AA를 지키기 위해 아래 두 값만 바꾼다.
  - **`--accent-bg-color`:** `#3584e4`(blue_3) 대신 `#1c71d8`(blue_4)를 쓴다. 흰 글자와의 대비가 3.9:1에서 4.9:1로 올라간다.
  - **`--dim-opacity`:** 55% 대신 70%를 쓴다. 흐리게 표시한 본문 글자도 4.5:1 이상을 유지한다.
- **그대로 두는 값:** 링크와 강조 글자색 `--accent-color`(#0461be / #81d0ff)는 원래 값으로 AA를 통과하므로 바꾸지 않는다.
- **적용 방식:** 모든 색은 `light-dark()`로 한 번만 선언한다. `data-theme` 속성으로 라이트/다크를 강제할 수 있다.
- **추가 (2026-10-04, ADR-0014 재디자인):**
  - **포커스 링:** `--focus-ring-color`를 강조색 50% 대신 80%로 쓴다(libadwaita의 고대비 값). 50%는 `#fafafb` 위에서 2.25:1이라 WCAG 1.4.11(3:1)에 못 미치고, 80%는 3.97:1이다. 강조색을 섞은 슬라이드 위에서는 80%도 2.89:1로 떨어지므로 그 안에서만 100%(라이트 3.72:1 이상, 다크 5.80:1 이상)를 쓴다.
  - **슬라이드 점 표시:** 현재 위치 점이 아닌 점의 불투명도를 libadwaita의 0.3 대신 0.55로 쓴다(라이트 3.21:1, 다크 5.75:1). 점은 장식이라 `aria-hidden`이고, 위치는 상태 영역으로 알린다.
  - **OSD 버튼:** libadwaita의 최소 32px 대신 44px로 만든다(WCAG 2.5.5와 터치 대상, Flathub도 44px).
  - **호버 높이:** 누를 수 있는 카드는 포인터를 올렸을 때만 그림자를 card에서 popover 단계로 올린다. 두 값 모두 libadwaita의 그림자이고, 움직임이나 크기 변화는 없다(`@media (hover: hover)`).
  - **색을 섞은 바탕 위 글자:** 강조색이나 경고색을 30% 섞은 바탕(슬라이드, 경고·위험 안내 상자) 위의 글자는 흐리게(dim) 쓰지 않는다. 70%로 흐리게 하면 밝은 바탕에서 4.27:1까지 떨어진다. 강조색 100%를 글자 뒤 바탕으로 쓰지 않는다(흰 글자 대비가 보라색만 4.5:1을 넘는다).

## ADR-0010 — 아이콘과 폰트 출처
- **아이콘:** Adwaita icon theme 51.0과 libadwaita 1.10.0의 symbolic 아이콘을 `currentColor`로 바꾸고 SVGO로 최적화해 `src/assets/icons/`에 둔다. 출처는 그 폴더의 `README.md`에 적는다.
  - 빌드할 때 인라인 SVG로 넣으므로 추가 요청이 없다.
- **폰트:** Adwaita Sans와 Mono 51.0을 쓴다.
  - **Adwaita Sans:** `opsz=14`로 고정하고 굵기 범위를 400–800으로 줄인 뒤 라틴 subset만 남겨 woff2로 만든다(약 33KB).
  - **Adwaita Mono:** 굵기 400과 700을 ASCII만 남겨 각 17KB로 만든다.
  - 라이선스는 OFL이며 `src/assets/fonts/OFL.txt`에 둔다. 예약 폰트명(RFN)이 없어 subset을 만들어도 이름을 바꿀 필요가 없다.

## ADR-0011 — CSP와 인라인 스크립트
- **문제:** Astro CSP는 `is:inline` 스크립트의 해시를 자동으로 넣지 않는다.
- **해결:** 테마 초기화 스크립트는 `src/scripts/theme-init.ts`의 문자열 하나로 관리한다. `Base.astro`에서 `Astro.csp.insertScriptHash()`로 그 해시를 등록한다.
- **검증:** 빌드 결과의 모든 인라인 script와 style 해시가 `.vercel/output/config.json`의 CSP 헤더에 들어 있는지 확인한다.

## ADR-0012 — 벡터 로고가 없는 배포판은 공식 PNG를 쓴다
- **문제:** antiX, Bodhi Linux, SparkyLinux처럼 공식 로고를 래스터 이미지로만 배포하는 프로젝트가 있다. 래스터를 SVG로 바꾸면(트레이싱) 공식 로고를 수정하는 셈이 된다.
- **결정:** 공식 SVG가 어디에도 없을 때만 공식 PNG를 쓴다.
  - `bun scripts/assets/raster-logo.ts <파일> <slug>`로 투명 여백만 잘라 내고 256px 안에 맞춰 줄인다. 색 변경, 팔레트 양자화, 확대는 하지 않는다.
  - `logo.file`은 `<slug>.png`, `logo.source`는 원본 PNG의 공식 URL로 적는다.
  - `scripts/validate-catalog.ts`가 형식(PNG), 크기(긴 변 128–512px), 용량(80KB 이하)을 검사한다.
- **영향:** 로고 URL과 OG 이미지 코드는 SVG와 PNG를 모두 받는다. 공식 SVG가 나오면 SVG로 바꾼다.

## ADR-0013 — "오늘의 인기 배포판"은 위키백과 조회수로 정한다 (2026-10-04)
- **결정:** 홈 맨 위 슬라이더의 순위는 Wikimedia Pageviews REST API가 주는 영어 위키백과(`en.wikipedia`) 문서 조회수로 매긴다.
  - 사람의 조회만 센다(`agent=user`, `all-access`, 일 단위).
  - 기준일은 집계가 끝난 가장 최근 UTC 하루(보통 어제)다. 전날 순위도 함께 저장해 순위 변동을 보여 준다.
  - 배포판과 문서의 연결은 편집자가 정한다(`scripts/sync/wikipedia-articles.ts`). 리다이렉트가 아닌 실제 문서 제목만 쓴다. 전용 문서가 없으면 `null`로 두고, 회사 문서나 상위 배포판 문서로 대신하지 않는다.
- **ADR-0008과의 관계:** ADR-0008은 다른 사이트의 인기 순위를 가져와 표시하지 않기로 했다. 이 결정은 그중 "인기 순위 표시"만 바꾼다.
  - DistroWatch는 여전히 쓰지 않는다.
  - 카탈로그 정렬(추천순, 이름순, 최근 업데이트순)은 그대로 둔다. 이 순위는 슬라이더에만 쓴다.
- **이유:**
  - Wikimedia가 공개한 공식 API다. 키가 필요 없고 조회수 데이터는 CC0다. 그래도 출처(위키백과 조회수, 기준일)는 화면에 밝힌다.
  - 우리 방문자를 추적하지 않는다. 쿠키, 분석 스크립트, 서버 기록이 필요 없으므로 개인정보 원칙과 정적 구조(ADR-0003)를 그대로 지킨다.
  - 하루 단위로 확정된 숫자라 같은 날에는 순위가 흔들리지 않는다.
- **영어판만 쓰는 이유:** 언어판마다 문서 유무와 제목이 달라 서로 비교할 수 없다. 영어판이 문서도 가장 많고 조회수도 가장 많다. 한국어판에는 문서가 없는 배포판이 많다.
- **동기화:**
  - `bun run sync -- --kind=popularity`로 실행한다(`all`에 포함된다). 6시간마다 도는 releases 실행에 함께 넣는다(`--kind=releases,popularity`).
  - 문서마다 최근 9일 치를 요청 한 번으로 받는다.
  - 파일에 이미 기준일 순위가 있으면 요청을 보내지 않는다. 기준일 집계가 아직 공개되지 않았으면 조회수가 가장 많은 문서 하나만 확인하고 멈춘다.
  - 순위를 매기는 날은 절반 넘는 문서에 데이터가 있는 가장 최근 날이다. 기준일이 일부 문서에만 공개됐을 때 몇 개만으로 순위를 매기지 않기 위해서다.
  - 문서 하나가 실패하면 그 배포판만 빠지고, 다음 실행에서 다시 받는다. 4분의 1 넘게 실패하거나 3번 연속 실패하면 기존 파일을 그대로 둔다. 10분 안에 받지 못한 문서도 실패로 센다(같은 작업의 releases 동기화가 시간 초과로 끊기지 않게).
  - `status.json`에는 기록하지 않으므로 실패해도 이슈를 열지 않는다. 실행 로그와 `report.json`에만 남는다.
- **한계:**
  - 영어 위키백과 문서가 없는 배포판(예: Vanilla OS, TUXEDO OS)은 순위에 나오지 않는다.
  - 오래되고 잘 알려진 배포판에 유리하다. Debian, Ubuntu처럼 일반 독자도 많이 찾는 문서는 실제 사용자 수와 상관없이 조회수가 높다.
  - 영어권 독자의 관심을 보여 줄 뿐, 설치 수나 다운로드 수가 아니다. 뉴스 하나로 하루만 순위가 튀기도 한다.
  - `agent=user`도 사람처럼 보이는 자동화 트래픽을 모두 걸러 내지는 못한다.
  - 문서 제목이 바뀌면 옛 제목은 리다이렉트가 되어 조회수가 거의 0이 된다. 순위가 이상하면 매핑부터 다시 확인한다.

## ADR-0014 — 더 단순한 Adwaita 화면과 "약간의 입체감" (2026-10-04)
- **배경:** 소유자가 디자인을 더 단순하게, GNOME Adwaita를 중심으로, 약간의 3D 느낌을 넣어 달라고 요청했다. 홈 맨 위에는 오늘의 인기 배포판 슬라이더를 둔다(순위는 ADR-0013).
- **입체감은 libadwaita의 어휘만 쓴다:**
  - **앱 아이콘 타일(AppTile):** 공식 로고를 GNOME 앱 아이콘 받침(밝은 윗면 + 어두운 앞면 + `.icon-dropshadow`) 위에 올린다. 모양은 HIG와 App Icon Preview 템플릿을 따른다(반경 = 면 × 8/104, 앞면 두께 = 면 × 4/128, 로고 영역 = 면의 75%, 가로로 긴 워드마크는 면 너비의 7/8). 크기는 24·36·48·64·96·128·160px이다. 로고 자체는 바꾸지 않으며(CLAUDE.md 규칙 8), 다크 모드에서 검은 로고가 보이지 않던 문제도 함께 해결된다.
  - **높이 단계:** card → raised → popover → dialog 그림자를 그대로 쓴다. 헤더는 libadwaita 툴바의 위쪽 막대 그림자(`--shadow-top-bar`)로 내용 위에 떠 있다. 누를 수 있는 카드는 포인터를 올렸을 때만 popover 그림자로 올라간다. 보기 전환기(ViewSwitcher)의 현재 항목은 toggle group처럼 raised 그림자를 쓴다.
  - **OSD 원형 버튼:** 슬라이더 화살표처럼 내용 위에 놓는 조작에는 libadwaita의 `.osd` 버튼(어두운 반투명 바탕)을 쓴다.
  - **쓰지 않는 것:** 그라디언트, 유리 효과(backdrop-filter), 버튼 베벨, 이동·확대 호버 효과, 색이 번지는 그림자, 페이지마다 다른 그림자. 다크 모드의 카드 그림자를 일부러 키우지 않는다(libadwaita도 거의 보이지 않는다).
- **강조색:** 슬라이드 등의 색은 libadwaita 강조색 9가지(`.accent-blue` … `.accent-slate`, `--tint`/`--tint-standalone`)만 쓴다. 인라인 `style` 대신 클래스로 넣어 CSP를 지킨다. 바탕에는 AdwBanner처럼 창 바탕색에 30%만 섞는다.
  - 배포판마다 어떤 강조색을 쓸지는 빌드할 때 공식 로고에서 정한다(`src/lib/brand-accent.ts`). 로고를 128px로 그려 회색이 아닌 픽셀(OKLCH 채도 0.04 이상)의 색상을 10° 단위로 모으고, 가장 무거운 색을 libadwaita의 `adw_accent_color_nearest_from_rgba()`와 같은 규칙으로 가장 가까운 강조색에 맞춘다. 색이 있는 픽셀이 5% 미만인 흑백 로고는 slate다. 결과가 어색하면 카탈로그의 `logo.accent`로 편집자가 9가지 중 하나를 지정한다. 로고 파일은 바꾸지 않는다.
  - 슬라이드 위에는 흐린(dim) 글자를 쓰지 않고, 강조색 단색 바탕 위에 글자를 올리지 않는다(흰 글자 대비가 4.5:1에 못 미친다).
- **탐색:**
  - 휴대폰의 하단 탭 막대를 없앤다. 탐색이 헤더, 하단 막대, 메뉴, 바닥글에 네 번 반복됐다.
  - 헤더에는 로고, 주요 탐색(넓은 화면), 검색, 주 메뉴만 둔다. 주 메뉴는 아이콘 없는 GNOME 주 메뉴 형식으로, 좁은 화면에서는 주요 목적지 4개를 먼저 보이고, 그다음 릴리스 소식·비교·소개, 화면 스타일, 다른 언어 하나를 둔다.
  - 한국어 퀴즈 이름을 "배포판 찾기"에서 "배포판 추천"으로 바꾼다(버튼은 "추천받기"). "찾기"는 검색으로 읽히기 때문이다. 주소 `/finder/`와 영어 이름은 그대로다.
  - 바닥글은 링크 한 줄(소개, 릴리스 소식, 비교, RSS, 소스 코드)과 법적 고지 한 줄(상표, 라이선스)만 둔다.
- **홈:** 화면용 h1은 숨기고, 인기 슬라이더 → 용도별 칩 한 줄 → 추천 배포판(슬라이더에 나온 배포판 제외) → 새 릴리스(배포판·시리즈마다 한 줄) → 리눅스 가이드 한 줄 순서로 둔다. 큰 소개 영역, 설명 문장, 통계 문구는 없앤다.
  - 슬라이더는 WAI-ARIA APG의 기본 캐러셀이다. JS가 없으면 그냥 가로 스크롤(scroll-snap) 줄이고, JS가 있으면 8초마다 넘긴다. 마우스를 올리면 잠시 멈추고, 키보드 초점이 들어오면 사용자가 다시 시작할 때까지 멈추며, 움직임 줄이기 설정에서는 멈춘 상태로 시작한다. 탭 순서는 자동 넘김 버튼 → 이전/다음 → 현재 슬라이드의 링크다.
  - 순위 데이터가 없으면(첫 동기화 전) 편집 순서의 배포판을 빌드 날짜마다 돌려 가며 "오늘의 추천 배포판"으로 순위 없이 보여 준다.
  - 새 릴리스와 릴리스 소식 페이지는 같은 묶음 규칙(`groupReleases()`)을 쓴다. 같은 달의 같은 시리즈는 최신 포인트 릴리스 한 줄로, 같은 날 나온 같은 시리즈의 파생판(Kubuntu 등)은 부모(Ubuntu) 줄로 합친다. RSS는 버전마다 항목을 그대로 둔다.
- **배포판 카드(DistroCard):** Flathub의 앱 카드처럼 64px 앱 아이콘 타일, 이름, 두 줄 소개만 둔다. 계열·릴리스 방식 배지는 없앤다(필터용 `data-*` 속성은 그대로).
- **배포판 상세:** 위쪽은 128px 타일(700px 미만은 96px), 이름, 소개, 버튼 두 개(다운로드, 설치 가이드)만 둔다. 사실 목록은 핵심 줄만 보이고 나머지는 "더 보기"로 접는다.
- **안내 상자(Callout):** 두 가지 모양만 쓴다. 참고·팁·정보·성공은 카드 바탕에 강조색 아이콘, 경고·위험만 색을 입힌다. 색은 실제 위험을 알릴 때만 쓴다.
- **접근성:** 이 결정으로 생긴 libadwaita 값 변경은 ADR-0009에 함께 적는다.

## ADR-0015 — Claude Code 스킬과 브라우저 검증 도구 (2026-10-05)
- **목표:** AI가 만든 UI가 템플릿처럼 보이지 않게 하고, 실제 브라우저에서 접근성과 성능을 숫자로 확인하게 한다. 기존 디자인(ADR-0006/0009/0014)과 구조를 바꾸지 않는다.
- **결정:** 프로젝트 범위의 스킬 5개를 `.claude/skills/`에 커밋한다. 로컬 세션과 Claude Code on the web 모두 저장소 클론에서 그대로 읽는다.
  - `frontend-design` (anthropics/claude-plugins-official, Apache-2.0): 수정 없이 복사한다. 새 팔레트나 글꼴을 제안해도 Adwaita 규칙이 우선한다(CLAUDE.md "Web quality").
  - `frontend-ui-engineering`, `browser-testing-with-devtools`, `performance-optimization`, `code-review-and-quality` (addyosmani/agent-skills, MIT): 각 SKILL.md 제목 아래에 "Linuxhub overlay" 블록을 넣어 이 프로젝트의 규칙(Astro + 바닐라 아일랜드, CSP, Adwaita 토큰, Bun, 실험실 측정만)을 먼저 적용한다. 출처 커밋과 바꾼 부분은 `.claude/skills/README.md`에 적는다.
  - addyosmani/web-quality-skills(MIT)는 설치하지 않는다. 겹치지 않는 WCAG 2.2 표와 LCP·INP·CLS 진단만 위 스킬의 참고 파일로 옮긴다. 나머지는 이미 있는 Lighthouse·axe 검사와 겹치거나 CSP를 어기는 예시가 있다.
- **플러그인으로 설치하지 않는 이유:** 저장소 설정의 `enabledPlugins`는 클라우드 세션에서 설치되지 않는다. 로컬에서 플러그인과 복사본을 함께 쓰면 같은 스킬이 두 번 뜬다.
- **MCP:** `.mcp.json`에 `chrome-devtools` 서버 하나를 둔다. `chrome-devtools-mcp@1.10.1`(Apache-2.0)로 버전을 고정하고, 헤드리스·임시 프로필로 띄운다. 사용 통계와 CrUX 조회는 끈다(규칙 9). 클라우드 컨테이너에서는 미리 설치된 Chromium을 쓴다. 로컬에서는 프로젝트 MCP 서버를 처음 한 번 승인해야 한다(Claude Code on the web 세션은 바로 연결된다).
- **성능 근거:** 실험실 측정(Lighthouse CI, DevTools 트레이스)만 쓴다. RUM이나 `web-vitals` 같은 수집 스크립트는 넣지 않는다(규칙 9, ADR-0013). 측정하지 않은 개선은 주장하지 않는다.

## ADR-0016 — 디자인 시스템 v2: "배포판을 위한 GNOME Software" (2026-10-06)
- **배경:** 소유자가 승인한 디자인 시스템 v2를 기존 기능과 업무 로직을 깨지 않고 적용한다. 순서는 토큰과 공통 컴포넌트 → 헤더·탐색·바닥글 → 핵심 페이지 → 입력과 상태 → 나머지 페이지 → 반응형·움직임·접근성 점검이다. 단계마다 기존 e2e를 통과시키고 실제 브라우저에서 확인한다.
  - 원칙: 기존 컴포넌트를 먼저 쓰고 같은 것을 두 번 만들지 않는다. 새 의존성과 필요 없는 JS를 넣지 않고, 시각 효과를 위해 성능을 내주지 않는다. 과한 둥근 카드, 그라디언트, 유리 효과, 그림자, 장식용 UI를 쓰지 않는다.
- **글자 크기는 8단계다:**
  - `--text-title-1` 32px(600px 미만 28px, 페이지마다 h1 하나), `--text-title-2` 22px(섹션 h2), `--text-title-3` 19px(h3, 슬라이드 제목), `--text-heading` 16px 굵게(카드 이름, h4. `--text-title-4`를 대신한다), `--text-body` 16px, `--text-prose` 17px(설치 가이드와 리눅스 가이드 본문), `--text-control` 15px(버튼, 콤보, 칩, 토글, 토스트), `--text-caption` 13px. 코드 블록은 `--text-code` 14px, 인라인 코드는 0.9em이다.
  - 쓰지 않던 `--text-display`와 `.title-display`를 없앤다. 줄 간격도 크기마다 토큰(`--line-height-*`)으로 정한다.
  - 굵기는 400·700·800만 쓴다. h1·h2의 굵기는 `--font-weight-title` 하나로 정하고 한국어에서는 700으로 낮춘다. 한글은 시스템 고딕이라 Adwaita Sans 800과 나란히 두면 굵기가 고르지 않다. 제목 자간은 영어에만 준다.
  - 본문 폭은 한국어 760px, 영어 55ch(590px)다. 영어 글 일곱 편(리눅스 가이드 여섯 장과 Fedora 설치 가이드)에서 Adwaita Sans 17px의 55ch는 꽉 찬 줄이 중앙값 68–71자, 90번째 백분위 73–75자, 최대 78자다. 56ch는 중앙값 70–72자(최대 80자), 60ch는 74–77자(최대 85자), 명세의 68ch는 85–88자(최대 95자)라 55ch로 정했다. 본문 줄 간격은 한국어 1.75, 영어 1.6이다.
  - 이 폭은 글 줄(문단, 목록, 인용, 단계, h2–h4)에만 건다. 표, 코드 블록, 목록 상자, 안내 상자는 글 칸 폭(760px)을 그대로 쓴다. 글 칸 전체를 590px로 줄이면 표의 줄이 모두 두 줄로 접히고, 글 아래의 출처·관련 배포판·이전/다음 링크나 오른쪽 목차와 어긋나 빈 띠가 생겼다.
  - 표는 1000px 미만에서 자기 안에서 가로로 스크롤하는 상자가 된다. 폭은 내용에 맞추되 글 칸보다 넓어지지 않는다. 표 상자는 가장 좁은 배치보다 줄어들지 않고 잘리지도 않아서, 그보다 좁은 글 칸(600–680px 화면)에서는 페이지 전체를 옆으로 밀었다. 지금 가장 넓은 표의 최소 폭은 626px이고, 1000px 이상에서는 모든 글 칸에 들어간다.
  - 고정폭 글꼴: Adwaita Mono는 코드 블록이 있는 페이지에서만 불러온다. 다른 페이지의 체크섬과 인라인 코드는 `--font-mono`의 대체 목록(`ui-monospace` …)으로 시스템 고정폭 글꼴을 쓴다. 전에는 변수가 비어 Sans로 보였다. 글꼴 요청을 늘리지 않으려고 상세·소개 페이지에 Adwaita Mono를 더 불러오지 않는다.
  - 날짜(`<time>`)는 고정폭 숫자(`tabular-nums`)로 맞춘다.
- **간격, 배치, 조작 크기:**
  - `--space-1…7`(6px 격자)은 그대로 둔다. 새 토큰은 `--space-section`(섹션 사이 48px, 600px 미만 36px), `--space-grid`(카드 격자 18px, 600px 미만 12px), `--sidebar-width` 240px, `--aside-width` 360px, `--prose-measure`다.
  - `--control-height`는 버튼·입력·콤보 36px, `--row-min-height`는 목록 줄 50px이고, 터치 화면(`pointer: coarse`)에서는 44px·56px이다.
  - 공통 배치 클래스(`.page`, `.page-header`, `.lead`, `.section`, `.section-header`, `.card-grid`, `.button-row`)를 `base.css`의 `utilities` 층에 둔다. 페이지는 이후 단계에서 옮긴다.
  - 중단점은 배치 600·1000px이고, 헤더만 768px(주요 탐색)과 1100px(검색 입력 모양 버튼)을 쓴다. 미디어 쿼리는 사용자 정의 속성을 읽지 못하므로 범위 문법에 숫자를 쓴다. 599/640/700/900/960px 쿼리는 파일을 고칠 때마다 바꾼다.
- **색:**
  - 강조색은 한 화면의 주 동작 하나, 본문 링크, 포커스 링, 선택 표시에만 쓴다. 상태색은 실제 위험(지원 종료, 6개월 안 지원 종료, 오래된 데이터, 체크섬 확인)에만 쓴다. Badge의 `accent` 색을 없애고, Banner는 `accent` 대신 `warning`(오래된 데이터)을 둔다.
  - 강조색 바탕(슬라이드, 상세 페이지 위쪽 띠)은 `--tint-bg-color` 하나로 정한다. 라이트는 지금처럼 창 바탕에 30%(sRGB)를 섞고, 다크는 `--tint-standalone`을 oklab으로 25% 섞는다. 명세의 18%에서는 파랑·청록·회청이 구별되지 않았고(스크린숏), 25%에서 흰 글자 대비는 8.98–10.20:1이다.
  - 앱 아이콘 타일은 다크 모드에서 윗면을 `#deddda`(light-3), 앞면을 `#9a9996`(새 `--light-5`)으로 바꿔 눈부심을 줄인다. 로고는 바꾸지 않는다.
- **아이콘은 뜻 하나에 하나만:**
  - `info.svg`는 upstream `dialog-information-symbolic`인데 Adwaita 51에서는 전구 모양이므로 `lightbulb.svg`로 이름을 바꾼다. 참고는 `about`(원 안의 i), 팁은 `lightbulb`, 경고는 `warning`이다.
  - 개발자는 `terminal`, 소스 코드 링크는 `engineering`, 기업은 `system`이다. 별(`star`)은 입문자 하나만 뜻하게 하고, 슬라이드 순위의 별과 미러의 "★"는 해당 페이지를 고칠 때 바꾼다.
  - `about.svg`와 `contents.svg`에 빠져 있던 `fill="currentColor"`를 넣어 검게 보이지 않게 한다.
- **컴포넌트:**
  - 카드는 세 종류만 쓴다. DistroCard(같은 종류 모음의 격자), BoxedList(줄 묶음), Callout(참고·팁·경고)이다. 쓰지 않던 변형(Button `opaque`, Callout `info`·`success`·`danger`)은 없앤다.
  - DistroCard는 타일 64px(600px 미만 48px), 이름 16px 굵게, 소개 두 줄(600px 미만 세 줄)이고, 카드 전체가 링크 하나다.
  - 사실 목록의 속성 줄은 목록 폭이 480px 이상일 때만 라벨(40%)과 값을 두 열로 놓는다(컨테이너 쿼리). 그래서 360px 옆 칸에서는 위아래로 쌓인다. 라벨 열은 줄 글자 영역이 아니라 목록 폭(`cqi`)으로 재므로, 끝에 날짜나 화살표가 있는 줄도 값이 같은 x에서 시작한다.
  - 펼침 줄(ExpanderRow)은 모두 `pan-down`을 180° 돌린다. 명세의 90° 회전은 허용 사항이고, 오른쪽 화살표는 같은 목록의 이동 화살표(`go-next`)와 헷갈린다. DocSources와 MDX `<Tab>`도 BoxedList와 ExpanderRow로 다시 만들어 손으로 만든 복사본을 없앤다. 탭 안의 코드 블록은 따로 바탕을 두지 않는다(카드 안의 카드 금지, 명세 §5). 고정폭 글꼴과 한 단계 들여쓰기로 구별하고, 목록 오른쪽 끝까지 이어져 긴 명령은 목록 가장자리 아래로 스크롤된다. Prism 색은 펼침 영역 바탕에서도 4.5:1 이상이다(가장 낮은 값: 라이트 4.79:1, 다크 4.57:1).
  - 단계 표시(Steps)의 숫자는 강조색 대신 기본 버튼 바탕에 놓는다. 숫자는 동작이 아니기 때문이다.
  - 새 공통 요소는 SearchEntry(채운 입력과 자체 지우기 버튼), toggle group(ViewSwitcher와 추천 퀴즈 선택지), `.adw-nav-row`(메뉴·목차·검색 결과 줄), `.adw-spinner`(네트워크를 300ms 넘게 기다릴 때만), `.checksum`(체크섬 글자)이다. 모두 `/design/` 쇼케이스에 둔다.
  - 현재 칩은 색만으로 구별하지 않도록 체크 아이콘을 함께 보인다. 체크 아이콘은 현재가 될 수 있는 칩(카탈로그의 필터 줄, `current`나 `aria-pressed`를 받은 칩)에만 넣는다. 홈과 계보의 바로가기 칩은 현재가 되지 않으므로 넣지 않는다(홈 문서 gzip 639B, 계보 221B). 카탈로그의 "전체" 칩에도 다른 칩처럼 아이콘(app-grid)을 두어, 현재 표시가 아이콘 자리를 바꿀 뿐 칩 폭이 바뀌어 줄이 밀리지 않게 한다. 강제 색상 모드에서는 카드, 목록(BoxedList), 안내 상자(Callout), 타일, 버튼, 칩, 토글, 입력, 콤보, 체크섬 상자에 투명 테두리를 그려 경계를 남긴다. 타일 윗면은 원래 색을 지켜 어두운 로고가 보이게 한다.
  - 누를 수 있는 카드는 호버할 때 지금처럼(ADR-0014) popover 그림자로 올라간다. raised는 card 그림자에서 1px 고리를 뺀 것이라 호버에 쓰면 카드의 가장자리가 사라져 오히려 낮아 보인다. 그래서 사다리에서 눈에 보이는 다음 단계인 popover를 쓰고, 같은 색 호버 덧칠은 그대로 둔다. 명세의 "raised로 한 단계" 문구도 이에 맞게 고쳤다. raised는 toggle group의 현재 항목에만 쓴다.
  - 코드 블록은 테두리 없이 채운 바탕이다. 라이트 바탕(`--light-2`)은 창 바탕과 거의 같아 가장자리가 약하지만, 더 어둡게 하면 Prism 주석 색이 4.5:1 아래로 내려가므로(`--button-color` 위 약 4.1:1) 지금은 두고 고대비 모드에서만 1px 고리를 그린다.
  - 상태 Badge(성공·경고·오류)는 바탕을 각 `*-bg-color` 10%로 칠하고 글자는 `*-color`다. 13px 굵은 글자가 창·카드 바탕에서 4.7:1 이상이다(라이트 성공 4.70/4.89, 다크 5.6 이상).
- **날짜와 크기:** 날짜 형식은 하나만 쓴다. 한국어는 "2026년 4월 23일", 영어는 "Apr 23, 2026"이고 슬라이드도 같다. `formatDate`와 `formatBytes`는 클라이언트에서도 쓸 수 있는 `src/lib/format.ts`로 옮기고, `catalog.ts`가 다시 내보낸다. 릴리스 소식은 달 제목 아래에서 일만 보인다. 같은 형식에서 달을 제목으로 뺀 것이라 두 번째 형식이 아니다.
- **움직임:** 토스트는 투명도로만 나타난다(8px 이동을 없앤다). 대화상자가 열리면 CSS(`html:has(dialog[open])`)로 페이지 스크롤을 막고, 그동안 스크롤 막대 자리를 남겨(`scrollbar-gutter: stable`) 페이지가 옆으로 밀리지 않게 한다. 스크롤 막대가 없는 짧은 페이지(일반 스크롤 막대를 쓰는 데스크톱)에서는 반대로 그 자리만큼(약 8px) 대화상자 뒤의 내용이 왼쪽으로 옮겨진다. 대부분의 페이지는 스크롤되므로 받아들인다.
- **성능 예산:**
  - CSS는 모든 페이지에 인라인된다. 이 단계에서 페이지마다 gzip 0.92–1.07KB가 늘었다(측정: 홈 +961B, 상세 +1065B, 설치 +922B, 가이드 +936B). 대부분은 페이지가 아직 쓰지 않는 새 공통 요소(입력, toggle group, 탐색 줄, 스피너, 배치 클래스)다. 그래서 F 단계 끝의 상한을 처음 계획한 +0.5KB에서 +1.5KB(gzip, 페이지당)로 올린다. 조건은 Lighthouse 100(실행마다 99 이상)과 LCP 2.0초 이하다. 이후 단계가 쓸 요소는 먼저 실어도 된다. 어느 페이지도, 어느 단계도 쓰지 않는 CSS는 지운다.
  - `/learn/` 문서는 lhci 정적 서버(gzip)에서 전송량이 13955B에서 14944B로 늘었다. 그래서 Lighthouse가 흉내 내는 첫 혼잡 창(10 × 1460B ≈ 14.6KB)을 넘고 왕복이 한 번(150ms) 늘었다. 실험실 LCP 중앙값은 1312ms에서 1509ms로 올랐지만 점수는 100이고 2.0초 아래다. 바꾸지 않은 페이지를 같은 크기로 채워도 같은 값이 나오므로 원인은 문서 크기다. Vercel이 보내는 brotli로는 12140B라 경계 아래에 있다. 이 증가는 받아들이고 C 단계 전에 다시 잰다. `/distros/`는 다음 경계(약 43.8KB)까지 약 2KB가 남았으므로 B–D 단계에서 지켜본다(추정).
- **이후 단계의 결정 (기존 e2e가 확인하는 동작은 그대로 둔다):**
  - 상세 페이지 위쪽의 다운로드 버튼을 기본(회색) 버튼으로 낮춘다. 파란 버튼 두 개가 상세 26쪽 중 25쪽에서 한 화면에 함께 보였다(390px, 1366px 측정). 파란 버튼은 다운로드 마법사의 마지막 버튼 하나다.
  - 상세 페이지는 개요 문서가 있을 때만 두 열(본문 + 360px 옆 칸)이고 없으면 한 열이다. 지금은 26쪽 모두 옆 칸이 더 길어 본문 아래에 빈 띠가 생긴다.
  - 문서가 아직 없는 설치 가이드는 `noindex`로 두고 Pagefind와 사이트맵에서 뺀다. 주소는 그대로 둔다. StatusPage는 404에만 쓰고, 다른 빈 상태는 컴포넌트 안의 한 줄로 바꾼다.
  - 다운로드 마법사는 사용자가 선택을 바꾼 뒤 데이터를 기다리는 동안에만 이전 링크와 체크섬을 지우거나 비활성화한다. 서버가 넣은 기본 링크와 체크섬은 그대로 둔다. 실패한 요청을 기억해 두지 않고, 8초가 지나면 오류와 다시 시도 버튼을 보인다.
  - 언어 전환은 링크를 가리키거나 포커스하거나 클릭할 때 쿼리와 해시를 붙인다(새 탭에서 열기와 링크 복사도 같은 주소). 서버의 `href`는 경로만 둔다.
  - 비교 페이지는 알 수 없는 `?d=` 값을 지금처럼 빼되, 뺐다는 안내를 더한다. 768px 미만에서는 같은 `<table>` 하나를 CSS로 쌓는다(칸을 복제하지 않는다).
  - 추천 퀴즈 선택지의 마크업은 바꾸지 않는다. 600px 이상에서 짧은 질문(경험, 개인정보)만 toggle group으로, 나머지는 48px 라디오 줄로, 여러 개 고르는 질문은 체크 줄로 보인다. 알약 모양은 쓰지 않는다.
  - 검색 대화상자의 제목이 h2, 결과 그룹 제목이 h3다. 두 아일랜드의 `normalize()`와 `el()`은 공유 모듈로 빼지 않는다. 빼면 모든 페이지에 요청이 하나 늘기 때문이다. 대신 두 복사본을 똑같이 맞추고 주석으로 알린다.
  - "곧 지원 종료"(6개월 안) 표시는 빌드할 때 계산한다. 데이터가 바뀔 때만 다시 빌드하므로(ADR-0003) 며칠 늦게 바뀔 수 있다.
- **ADR-0009 고침:**
  - 포커스 링 100%를 슬라이드 안뿐 아니라 강조색 바탕(`.accent-*`) 전체에 쓴다. 600px 이상의 슬라이드 화살표에서 라이트 3.60–4.12:1, 다크 5.86–7.01:1이다(측정). 흰색 90% 링은 어두운 미디어 위 OSD용인데 지금은 쓰는 곳이 없다.
- **ADR-0014 고침:**
  - 슬라이더의 자동 넘김을 없앤다. 화살표, 점, 스와이프로만 넘긴다. 슬라이드 5개, `inert`, 점, 상태 문구, 처음과 끝의 이어짐, 3KB 미만 예산은 그대로이고, 탭 순서는 "순위 안내 → 이전 → 다음 → 슬라이드 링크"가 된다.
  - 헤더의 주요 탐색은 배포판·리눅스 가이드·배포판 추천·비교다. 계보는 주 메뉴로 옮기고, 주요 탐색은 768px부터 보인다. 현재 항목은 toggle group의 raised 흰 항목이다. 흰 항목과 toggle group 바탕의 대비는 라이트 1.19:1, 다크 1.78:1(측정)이라 그것만으로는 구별이 약하다. 그래서 현재 항목이 있는 동안 나머지 항목의 글자를 `--dim-opacity`로 흐리게 하고, 강제 색상 모드에서는 흐리게 하지 않고 현재 항목을 메뉴의 현재 줄처럼 `Highlight`로 채운다. 채운 항목의 포커스 링은 채움 안쪽(-4px)에 `HighlightText`로 그린다. 가장자리에 그리면 페이지 바탕과 같은 색이 되어 보이지 않는다. 주 메뉴는 키보드 포커스가 메뉴와 메뉴 버튼 밖으로 나가면 닫힌다.
  - 헤더의 두 경계(주요 탐색 768px, 검색 입력 모양 1100px)는 px과 em을 함께 쓴다(`(width >= 768px) and (width >= 48em)`, `(width >= 1100px) and (width >= 68.75em)`). 미디어 쿼리의 em은 브라우저의 글꼴 크기 설정을 따르므로, 글꼴을 크게 설정하면 rem 크기의 항목이 들어갈 폭이 될 때까지 탐색이 메뉴에 남는다. px만 쓰면 영어에서 125%일 때 "Compare"가, 150%일 때 "Distro Finder"도 잘려 마우스로 닿을 수 없었다(측정). 계획 §0.7의 "px 리터럴" 규칙에서 헤더만 벗어난다. 탐색은 줄어들거나 스크롤되지 않으므로 넘치면 헤더가 넘쳐 측정에서 바로 드러난다.
  - Callout은 참고·팁·경고 세 가지만 쓴다. 참고와 팁은 카드 바탕에 강조색 아이콘, 경고만 색을 입힌다.
- **CLAUDE.md:** "Typography" 줄이 없앤 `--text-display`를 글자 단계의 시작으로 적고 있다. 소유자의 파일이라 고치지 않고 알린다. 지금 글자 단계는 `--text-title-1` … `--text-caption`이다.
