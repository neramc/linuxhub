# 콘텐츠 작성 가이드

## 원칙
1. **베끼지 않는다.** 공식 문서를 그대로 옮기지 말고 이해한 내용을 자기 말로 다시 쓴다. 명령어와 고유명사는 그대로 써도 된다.
2. **출처를 남긴다.** frontmatter `sources`에 참고한 공식 문서 URL을 모두 적는다.
3. **검토일을 적는다.** frontmatter `lastReviewed`에 마지막으로 확인한 날짜(YYYY-MM-DD)를 적는다.
4. **바뀌는 값은 데이터 컴포넌트로 넣는다.** 버전, 파일명, 체크섬, 크기를 손으로 쓰지 않는다. `<Latest/>`, `<IsoName/>`, `<VerifyCommand/>` 같은 데이터 컴포넌트를 쓴다.
5. **두 언어를 함께 낸다.** 한국어와 영어를 같은 커밋에 넣는다. 영어는 번역투가 아니라 자연스러운 영어로 쓴다.
6. **겹치는 단계는 공용 partial을 쓴다.** USB 만들기, 체크섬과 서명 검증, UEFI와 Secure Boot, 듀얼부팅처럼 여러 배포판에 공통인 단계는 `src/content/partials/`의 공용 partial로 처리한다.

## 배포판 소개 (`overview.mdx`)
- 2~4개 문단, 한국어 기준 300~600자.
- 담을 내용: 무엇인지, 누구에게 맞는지, 특징(릴리스 모델, 기본 데스크톱 환경, 패키지 관리), 장점과 주의할 점.

## 설치 가이드 (`install.mdx`), 공식 문서 수준
아래 순서를 지킨다.
1. **시작하기 전에:** 시스템 요구사항, 백업, 듀얼부팅 여부
2. **다운로드와 검증:** 다운로드 마법사 링크, 체크섬, 가능하면 GPG 서명까지
3. **부팅 USB 만들기:** Windows, macOS, Linux별로 안내
4. **펌웨어 설정:** UEFI/BIOS 부팅 순서, Secure Boot 지원 여부
5. **설치:** 설치 프로그램 화면 순서대로 단계별로 설명. 파티션은 자동/수동, 암호화 옵션을 다룬다
6. **설치 후 할 일:** 업데이트, 드라이버(GPU, Wi-Fi), 코덱, Flatpak 등
7. **문제 해결:** 자주 막히는 지점
8. **공식 문서와 커뮤니티 링크**

## 문체
- 한국어는 "~합니다" 체로 쓴다. 군더더기 수식어를 빼고, 명령형 지시는 짧게 쓴다.
- 코드 블록에는 언어를 표기한다(`bash`, `text` 등). 프롬프트 기호(`$`)는 넣지 않는다.
- 위험한 작업(디스크 지우기 등)은 `<Callout type="warning">`으로 경고한다.
