# Internationalization

## Stack

A **hand-rolled, Paraglide-shaped runtime** in `packages/i18n` (ADR-0016),
which the project will keep through v1 rather than adopting the inlang
compiler (**ADR-0022** — decided 2026-08-04, with the measurable trigger for
revisiting it). Message catalogs + the locale registry live in `packages/i18n`
and are the single runtime source; this table is the canonical human-readable
registry.

Two consequences to know before writing i18n code:

- Call sites use **property access** — `m.some_key`, not `m.some_key()`. The
  function-call form arrives only if the compiler is adopted.
- Catalogs are **statically imported** into one `CATALOGS` map, so every
  authored locale ships to every visitor. Harmless at two catalogs (~19 KB);
  it is the first thing to fix as that number grows — see ADR-0022.

## Routing

- Locale prefix on every UI route: `/ko/explore`, `/ar/distro/fedora`.
- Prefix validated by a SvelteKit param matcher against the registry;
  unknown → 404.
- `/api/*` routes are never locale-prefixed; content language via `?locale=`.

## Geo detection & redirect

1. Request without locale prefix → look up country
   (Cloudflare `request.cf.country` on the Worker / Vercel geo headers on the
   edge for the web app).
2. Map country → default locale via `KV_GEO` (`geo:<country>`, 30 d TTL;
   mapping table maintained in `packages/i18n`).
3. Redirect **once** to the localized route and set the locale cookie.
4. A cookie / explicit user choice (LocaleSwitcher) always overrides geo;
   never re-redirect a user who has a stored preference.
5. `Accept-Language` is the tiebreaker when a country maps to multiple locales.

## RTL

RTL locales: **`ar`, `he`, `fa`, `ckb`**. Root layout sets
`<html dir="rtl" lang="…">`. All styles use logical properties; icons with
inherent direction (arrows, chevrons) flip via a shared utility. Every screen
is verified mirrored in the a11y gate (Playwright screenshot pass in `ar`).

## UI strings

- 100% of UI strings via `packages/i18n` messages — hardcoded strings are a
  review blocker (quality gate).
- English is authored first and is the complete reference catalog.
- Missing translation → English fallback automatically; no runtime errors.
- Dates, numbers, file sizes via `Intl` with active locale.

## Content (MDX) translation strategy

Distro docs (`content/distros/<slug>/<locale>/`) are translated
**progressively**: English first, then high-traffic locales (initial set:
`ko`, `ja`, `zh-Hans`, `de`, `fr`, `es`, `pt-BR`, `ru`). When a locale is
missing, serve English with `translated: false` and show the "untranslated"
badge. Translation coverage is reported by `GET /api/v1/stats/languages`.

## Workflow

1. Add/change a message in the `en` catalog (with the feature, same commit).
2. Machine-translate placeholder + mark for review, or leave missing
   (fallback covers it) — never ship broken interpolations.
3. Reviewed translations replace placeholders over time. There is no inlang
   project file while ADR-0022 stands; a new locale is one
   `packages/i18n/src/messages.<code>.ts` file added to the `CATALOGS` map.
