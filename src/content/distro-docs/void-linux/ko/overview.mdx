Void Linux는 다른 배포판을 고쳐 만든 것이 아니라 처음부터 새로 만든 독립 배포판으로, 소수의 자원봉사 개발자가 여가 시간에 개발합니다. 롤링 릴리스 방식이지만 가장 새로운 버전을 먼저 받는 것보다 안정성을 앞세우며, 한 번 설치한 뒤 꾸준히 업데이트하며 쓰도록 만들어졌습니다. 이름은 C 언어의 `void`에서 따왔고 특별한 뜻은 없습니다.

### 특징

- **직접 만든 패키지 관리자 XBPS.** 패키지 관리자 XBPS와 빌드 시스템 `xbps-src`를 처음부터 직접 작성했습니다. XBPS는 업데이트할 때 공유 라이브러리가 호환되지 않는 버전으로 바뀌어 의존성이 깨지지 않는지 검사하며, `xbps-install -Su` 한 번으로 시스템 전체를 업데이트합니다.
- **systemd 대신 runit.** 부팅과 서비스 감독을 단순한 구조의 runit이 맡습니다. 서비스는 실행 중인 서비스 디렉터리(`/var/service`)에 심볼릭 링크를 만들면 켜지고, 링크를 지우면 꺼집니다.
- **glibc와 musl 중 선택.** 흔히 쓰이는 glibc 외에 표준을 엄격히 따르는 가벼운 C 라이브러리 musl도 정식으로 지원합니다. 공식 저장소의 호환 패키지는 두 가지로 모두 빌드되고, musl과 맞지 않는 소프트웨어는 개발자들이 패치해 업스트림에도 보냅니다. systemd를 쓰지 않기에 가능한 선택입니다.
- **소스 빌드가 쉬운 구조.** `xbps-src`는 Linux 네임스페이스로 격리한 환경에서 root 권한 없이 패키지를 빌드하고, 다른 아키텍처용 크로스 컴파일도 지원합니다.

### 에디션과 변형

- 아키텍처마다 명령줄만 있는 **base** 이미지와 Xfce 데스크톱을 담은 **xfce** 이미지가 있고, 각각 glibc판과 musl판이 있습니다(i686은 glibc만). 다른 데스크톱도 지원하지만, 시험 부담을 줄이려고 설치 이미지로는 내지 않습니다.
- Apple Silicon용 라이브 이미지, Raspberry Pi 같은 ARM 보드에 바로 쓰는 플랫폼 이미지, 직접 나눈 파티션이나 chroot 설치에 쓰는 rootfs tarball도 있습니다.

### 이런 분께 맞습니다

- systemd 없이 단순한 init 시스템으로 돌아가는 리눅스를 원하는 사람
- 최소 구성에서 시작해 시스템을 직접 꾸려 가려는 숙련 사용자
- 사양이 낮은 컴퓨터나 musl 기반의 작은 시스템을 다루려는 사람
- 패키지를 소스에서 빌드하거나 패키징에 기여하고 싶은 개발자

### 알아 둘 점

- musl판에서는 glibc만 지원하는 독점 소프트웨어가 돌아가지 않는 경우가 많고, 특히 NVIDIA 독점 드라이버는 musl을 지원하지 않습니다. 이런 앱은 Flatpak이나 glibc chroot로 실행할 수 있습니다.
- 독점 라이선스 소프트웨어는 기본으로 켜져 있지 않은 nonfree 저장소에 있으며, `void-repo-nonfree` 패키지를 설치하면 켜집니다. 32비트 라이브러리를 담은 multilib 저장소는 glibc판에만 있습니다.
- 설치 프로그램 `void-installer`는 텍스트 메뉴 방식입니다. Xfce 이미지에서 데스크톱까지 설치하려면 네트워크 설치가 아닌 로컬 설치를 골라야 합니다.
- XBPS는 업데이트한 서비스를 자동으로 다시 시작하지 않으므로 필요하면 직접 재시작합니다. 수동 조치가 필요한 변경은 홈페이지 뉴스에 공지됩니다.

### 간단한 역사

void-packages의 첫 Git 기록은 2008년 9월, XBPS는 2009년 8월에 남아 있습니다. 2013년에 musl 툴체인이 처음 들어왔고, 한동안 쓰던 systemd를 2014년 7월 runit으로 바꾸었습니다.
