리눅스(Linux)는 Windows나 macOS처럼 컴퓨터를 움직이는 운영체제의 한 갈래입니다. 엄밀히 말하면 "리눅스"는 운영체제 한가운데에서 하드웨어를 다루는 **커널(kernel)**의 이름이고, 우리가 내려받아 설치하는 "리눅스"는 그 커널에 수많은 프로그램을 더해 하나로 묶은 **배포판(distribution)**입니다. 이 장에서는 이 구분부터 시작해 리눅스가 어디에서 쓰이는지, 그리고 누구나 무료로 쓰고 고칠 수 있는 이유가 무엇인지 차근차근 살펴봅니다.

## 커널과 운영체제는 다릅니다

커널은 운영체제의 심장과 같은 프로그램입니다. 컴퓨터를 켜면 가장 먼저 메모리에 올라가 전원이 꺼질 때까지 다음과 같은 일을 맡습니다.

- **CPU 시간 나누기**: 여러 프로그램이 동시에 돌아가는 것처럼 보이도록 실행 순서를 정합니다(멀티태스킹).
- **메모리 관리**: 프로그램마다 쓸 메모리를 나눠 주고, 서로의 영역을 침범하지 못하게 막습니다(가상 메모리).
- **장치 제어**: 디스크, 그래픽 카드, 키보드, 네트워크 카드 같은 하드웨어를 드라이버(driver)로 다룹니다.
- **파일과 네트워크**: 파일을 저장하고 읽는 방법, 인터넷으로 데이터를 주고받는 방법을 제공합니다.

프로그램은 하드웨어를 직접 만지지 않고, **시스템 콜(system call)**이라는 정해진 창구로 커널에 일을 부탁합니다. 그런데 커널 혼자서는 화면에 창을 띄우거나 웹 페이지를 열 수 없습니다. 실제로 쓸 수 있는 운영체제가 되려면 아래처럼 여러 층이 함께 있어야 합니다.

| 층 | 하는 일 | 리눅스 시스템에서의 예 |
|---|---|---|
| 애플리케이션 | 사용자가 직접 쓰는 프로그램 | Firefox, LibreOffice, 게임 |
| 데스크톱 환경 | 창, 메뉴, 설정 화면 | GNOME, KDE Plasma, Xfce |
| 그래픽 스택 | 화면에 그림을 그리는 바탕 | Wayland, X11 |
| 시스템 서비스 | 부팅, 로그인, 네트워크 관리 | systemd, NetworkManager |
| 기본 도구와 라이브러리 | 셸, 파일 명령어, C 라이브러리 | Bash, GNU coreutils, glibc |
| 커널 | 하드웨어와 자원 관리 | Linux |

지금 쓰는 시스템의 커널 버전과 배포판 이름은 터미널에서 바로 확인할 수 있습니다.

```bash
uname -r
cat /etc/os-release
```

첫 줄은 실행 중인 커널 버전을, 둘째 줄은 배포판 이름과 버전을 보여 줍니다. 터미널이 처음이라면 [터미널 기초](../terminal-basics/)를 먼저 읽어도 좋습니다.

kernel.org는 리눅스를 리누스 토르발스(Linus Torvalds)가 인터넷의 여러 개발자와 함께 처음부터 새로 작성한 유닉스(Unix) 복제품으로 소개하며, POSIX 같은 유닉스 표준을 따르는 것을 목표로 한다고 설명합니다. 그래서 리눅스는 유닉스의 코드를 물려받지 않았지만 구조와 사용법이 닮은 **유닉스 계열(Unix-like)** 운영체제로 분류됩니다. 유닉스 이야기는 [리눅스의 역사](../history/)에서 자세히 다룹니다.

## GNU와 리눅스: 이름에 얽힌 이야기

1980년대 초 리처드 스톨먼(Richard Stallman)은 누구나 자유롭게 쓰고 고칠 수 있는 유닉스 호환 운영체제를 만들기 위해 **GNU 프로젝트**를 시작했습니다. GNU는 "GNU's Not Unix"의 줄임말로, 이름 안에 자기 자신이 다시 들어 있는 재귀 약어입니다. 1990년 무렵 GNU에는 컴파일러, 편집기, 셸, C 라이브러리처럼 운영체제에 필요한 부품이 거의 다 갖춰졌지만, 정작 커널(GNU Hurd)은 개발이 늦어지고 있었습니다.

바로 그 무렵인 1991년, 리누스 토르발스가 유닉스와 호환되는 커널을 만들어 공개했습니다. 처음에는 자체 라이선스를 썼지만 1992년 자유 소프트웨어로 바뀌었고, 이때부터 GNU의 도구들과 리눅스 커널을 합쳐 처음부터 끝까지 자유 소프트웨어로 된 운영체제를 꾸릴 수 있게 되었습니다.

이 때문에 자유 소프트웨어 재단(FSF)은 이 조합을 **GNU/Linux**라고 불러 달라고 요청합니다. 시스템의 상당 부분이 GNU 소프트웨어이고, GNU 프로젝트가 처음부터 완전한 운영체제를 목표로 했다는 이유에서입니다. 반면 일상에서는 그냥 "리눅스"라고 부르는 사람이 대부분입니다. 이 가이드도 읽기 편하도록 운영체제 전체를 "리눅스"라고 부르되, 커널만 가리킬 때는 "리눅스 커널"이라고 구분해 씁니다.

<Callout type="note" title="커널이 같아도 운영체제는 다를 수 있습니다">

Android도 리눅스 커널을 바탕으로 하지만, 그 위에서 앱이 돌아가는 방식과 기본 구성 요소는 데스크톱 배포판과 크게 다릅니다. 같은 커널 위에 전혀 다른 모습의 운영체제를 세울 수 있다는 좋은 예입니다.

</Callout>

## 배포판이 더하는 것

커널과 GNU 도구만으로는 아직 "설치해서 바로 쓰는" 운영체제가 아닙니다. 수천 개의 프로그램을 골라 서로 잘 맞게 빌드하고, 설치 프로그램과 업데이트 방법까지 갖춰 하나로 묶어 내놓는 것이 **배포판**입니다. Ubuntu, Fedora, Debian, Linux Mint, Arch Linux가 모두 배포판입니다.

배포판은 대체로 다음과 같은 것을 정합니다.

- **패키지 관리자(package manager)**: 프로그램을 설치·업데이트·삭제하는 도구와, 프로그램을 모아 둔 소프트웨어 저장소(repository). 예를 들어 Debian 계열은 `apt`, Fedora는 `dnf`, Arch Linux는 `pacman`을 씁니다.
- **릴리스 방식**: 정해진 주기마다 큰 버전을 내는 **고정 릴리스(fixed release)**인지, 끊임없이 최신 버전으로 갱신되는 **롤링 릴리스(rolling release)**인지.
- **기본 데스크톱 환경**: 처음 켰을 때 보이는 화면과 함께 설치되는 기본 앱.
- **설치 프로그램과 기본 설정**: 파일 시스템, 보안 설정, 드라이버를 넣는 방식.
- **지원 기간과 철학**: 몇 년 동안 보안 업데이트를 제공할지, 독점(proprietary) 드라이버나 코덱을 기본으로 넣을지.

같은 엔진을 쓰는 자동차라도 회사마다 차체와 편의 장비가 다르듯, 배포판도 같은 커널 위에서 저마다 다른 경험을 줍니다. 배포판 고르는 법은 [배포판](../distributions/), 프로그램 설치 방식은 [패키지 관리](../package-management/), 화면 구성은 [데스크톱 환경](../desktop-environments/) 장에서 이어집니다.

## 리눅스가 돌아가는 곳

리눅스 커널은 처음에 386 PC용으로 만들어졌지만, 지금은 x86과 ARM, PowerPC를 비롯한 여러 프로세서 구조에서 32비트와 64비트로 모두 돌아갑니다. 덕분에 쓰이는 곳도 매우 넓습니다.

| 분야 | 어떻게 쓰이나 |
|---|---|
| 서버와 클라우드 | 웹 서비스, 데이터베이스, 클라우드 가상 머신의 운영체제로 널리 쓰입니다. Red Hat Enterprise Linux, Ubuntu Server, Debian 같은 배포판이 대표적입니다. |
| 스마트폰 | Android의 커널은 리눅스의 장기 지원(LTS) 커널에 Android용 패치를 더해 만듭니다. |
| 임베디드와 IoT | 공유기, TV, 산업용 장비처럼 특정 용도의 기기에 들어갑니다. Yocto Project 같은 도구로 기기에 꼭 맞는 리눅스 시스템을 만듭니다. |
| 슈퍼컴퓨터 | 세계에서 가장 빠른 컴퓨터 순위인 TOP500의 최상위 시스템들은 RHEL, HPE Cray OS 같은 리눅스 기반 운영체제를 씁니다. |
| 데스크톱과 게임기 | 개인용 PC와 노트북은 물론, Valve의 휴대용 게임 PC Steam Deck에 들어가는 SteamOS도 리눅스 기반입니다. |

리눅스를 직접 써 보지 않았더라도, 스마트폰이나 즐겨 찾는 웹 서비스를 통해 이미 매일 리눅스를 쓰고 있을 가능성이 큽니다.

## 자유 소프트웨어와 오픈 소스

리눅스가 이렇게 넓게 퍼진 데에는 기술만큼이나 **라이선스**가 큰 역할을 했습니다. 리눅스 커널과 GNU 프로그램은 **자유 소프트웨어(free software)**입니다. 여기서 "자유(free)"는 가격이 아니라 권리를 뜻합니다. GNU 프로젝트는 다음 네 가지 자유를 모두 보장해야 자유 소프트웨어라고 정의합니다.

| 번호 | 자유 | 쉽게 말하면 |
|---|---|---|
| 0 | 실행할 자유 | 어떤 목적으로든 원하는 대로 프로그램을 돌릴 수 있습니다. |
| 1 | 연구하고 고칠 자유 | 프로그램이 어떻게 동작하는지 살펴보고 바꿀 수 있습니다. 그러려면 소스 코드가 있어야 합니다. |
| 2 | 다시 나눌 자유 | 복사본을 다른 사람에게 줄 수 있습니다. |
| 3 | 고친 것을 나눌 자유 | 수정한 버전을 배포해 모두가 그 개선의 혜택을 보게 할 수 있습니다. |

자유 소프트웨어라고 해서 꼭 공짜일 필요는 없습니다. 복사본을 돈을 받고 팔아도 되고, Red Hat처럼 소프트웨어는 공개하면서 기술 지원과 유지보수를 구독 형태로 판매하는 기업도 있습니다.

1998년에는 **오픈 소스(open source)**라는 용어가 새로 생겼고, 같은 해 세워진 오픈 소스 이니셔티브(OSI)가 10가지 기준으로 된 "오픈 소스 정의"를 관리합니다. 두 용어가 가리키는 소프트웨어는 대부분 겹칩니다. 다만 자유 소프트웨어 진영은 사용자의 자유라는 가치를, 오픈 소스 진영은 소스 공개와 협업이 주는 실용적인 이점을 더 앞세운다는 차이가 있습니다. 둘을 합쳐 FOSS(Free and Open Source Software)라고 부르기도 합니다.

## GPL을 쉬운 말로

리눅스 커널은 **GNU 일반 공중 사용 허가서(GNU General Public License, GPL)** 버전 2를 따릅니다. GPL은 저작권을 거꾸로 활용해 소프트웨어가 계속 자유롭게 남도록 하는 **카피레프트(copyleft)** 라이선스입니다. 핵심만 추리면 다음과 같습니다.

- **누구나 어떤 목적으로든 쓸 수 있습니다.** 개인, 학교, 기업 모두 마찬가지입니다.
- **고쳐서 혼자 쓰는 것은 자유입니다.** 수정한 버전을 개인이나 회사 안에서만 쓴다면 공개할 의무가 없습니다.
- **배포할 때는 소스도 함께 줘야 합니다.** 수정본을 다른 사람에게 배포한다면, 받는 사람도 같은 GPL 조건으로 소스 코드를 얻을 수 있어야 합니다.
- **자유는 대물림됩니다.** GPL 프로그램을 고치거나 다른 코드와 합쳐 배포하는 경우, 그 결과물도 자유 소프트웨어로 남아야 합니다.

OSI가 승인한 라이선스 중에는 MIT, BSD, Apache 2.0처럼 이런 조건이 훨씬 가벼운 **허용형(permissive)** 라이선스도 있습니다. 어떤 라이선스를 고르느냐는 만든 사람의 선택입니다.

리눅스 커널의 라이선스에는 중요한 단서가 하나 붙어 있습니다. 프로그램이 시스템 콜로 커널과 대화하는 것만으로는 GPL 조건이 그 프로그램까지 넘어가지 않는다는 점을 명시한 것입니다(Linux-syscall-note). 덕분에 리눅스 위에서는 자유 소프트웨어뿐 아니라 상용 게임이나 업무용 프로그램 같은 독점 소프트웨어도 문제없이 돌아갈 수 있습니다.

<Callout type="note" title="법률 자문이 아닙니다">

이해를 돕기 위해 개념을 단순하게 정리했습니다. 소프트웨어를 배포하거나 사업에 활용하려면 라이선스 원문과 GNU 프로젝트의 [GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html)를 직접 확인하세요.

</Callout>

## 한눈에 정리

- **리눅스 커널**은 하드웨어와 자원을 관리하는 운영체제의 핵심입니다.
- 커널에 **GNU 도구**, 데스크톱 환경, 앱을 더해 묶은 것이 **배포판**이고, 흔히 이 전체를 "리눅스"라고 부릅니다.
- 리눅스는 서버, 스마트폰, 임베디드 기기, 슈퍼컴퓨터, 데스크톱까지 거의 모든 곳에서 돌아갑니다.
- 리눅스는 누구나 쓰고, 연구하고, 고치고, 나눌 수 있는 **자유 소프트웨어**이며, 커널은 **GPL 버전 2**를 따릅니다.

다음 장 [리눅스의 역사](../history/)에서는 유닉스에서 오늘날의 리눅스까지 이어지는 이야기를 따라갑니다.
