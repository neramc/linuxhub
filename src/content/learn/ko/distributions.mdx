리눅스(Linux)라는 이름은 엄밀히 말해 운영체제의 심장인 커널(kernel)만을 가리킵니다. 커널만으로는 컴퓨터를 쓸 수 없기 때문에, 여러 프로젝트가 커널에 도구·라이브러리·설치 프로그램·데스크톱을 묶어 바로 쓸 수 있는 운영체제로 만들어 배포합니다. 이것이 **배포판(distribution, 줄여서 distro)** 입니다.

배포판은 수백 가지가 있지만 대부분 몇 개의 큰 **계열(family)** 로 묶을 수 있고, 업데이트 방식도 몇 가지 유형으로 나뉩니다. 이 두 가지만 알아도 배포판 이름이 훨씬 덜 낯설어집니다.

## 배포판은 무엇으로 이루어지나

배포판마다 겉모습은 달라도 안을 들여다보면 비슷한 부품으로 이루어져 있습니다.

| 구성 요소 | 하는 일 | 예 |
|---|---|---|
| 커널 | 하드웨어를 관리하고 프로그램에 자원을 나눠 줍니다 | Linux |
| 기본 도구와 라이브러리 | 셸, 파일 도구, C 라이브러리 같은 기초 프로그램 | GNU coreutils, glibc, musl |
| init 시스템 | 부팅 후 서비스를 켜고 관리합니다 | systemd, OpenRC, runit |
| 패키지 관리자와 저장소 | 프로그램을 설치·업데이트·삭제합니다 | APT, DNF, pacman, zypper |
| 설치 프로그램 | 디스크를 나누고 시스템을 설치합니다 | Calamares, Anaconda |
| 데스크톱 환경 | 화면, 창, 메뉴, 설정 앱 | GNOME, KDE Plasma, Xfce |

GNU 프로젝트가 이 조합을 "GNU/Linux"라고 부르자고 하는 이유도 여기에 있습니다. 커널은 Linux이지만 그 위의 기본 도구 상당수는 GNU 프로젝트에서 왔기 때문입니다. 자세한 배경은 [리눅스란 무엇인가](../what-is-linux/)에서 다룹니다.

배포판끼리 실제로 다른 점은 크게 네 가지입니다.

- **패키지 형식과 도구**: `.deb`와 APT, `.rpm`과 DNF처럼 계열마다 다릅니다. 자세한 내용은 [패키지 관리](../package-management/)에서 설명합니다.
- **릴리스 모델**: 몇 달이나 몇 년마다 새 버전을 내는지, 끊임없이 조금씩 업데이트하는지.
- **기본값**: 어떤 데스크톱 환경과 앱, 파일 시스템, 설정을 처음부터 넣어 두는지.
- **운영 주체와 철학**: 회사가 만드는지 커뮤니티가 만드는지, 편의와 단순함 중 무엇을 우선하는지.

## 배포판 계열

새 배포판은 대개 처음부터 만들지 않고, 이미 있는 배포판의 패키지와 저장소를 바탕으로 자기 기본값과 도구를 더해 만듭니다. 그래서 "Ubuntu 기반", "Arch 기반" 같은 말이 나옵니다. 같은 계열이면 패키지 형식과 명령어가 같아서 문서와 노하우를 상당 부분 그대로 쓸 수 있습니다.

| 계열 | 패키지 형식 · 도구 | 대표 배포판 |
|---|---|---|
| Debian · Ubuntu | `.deb` · APT | Debian, Ubuntu, Linux Mint, Pop!\_OS, Zorin OS, Kali Linux |
| Fedora · RHEL | `.rpm` · DNF | Fedora, CentOS Stream, RHEL, AlmaLinux, Rocky Linux |
| Arch | pacman · AUR | Arch Linux, Manjaro, EndeavourOS, CachyOS |
| SUSE | `.rpm` · zypper | openSUSE Tumbleweed, openSUSE Leap, SUSE Linux Enterprise |
| 독립 | 저마다 다름 | Gentoo, Slackware, Alpine Linux, Void Linux, NixOS |

계열 사이의 부모·자식 관계는 [배포판 계보](../../family/)에서 나무 모양으로 볼 수 있습니다.

### Debian과 Ubuntu 계열

**Debian**은 커뮤니티가 만드는 오래된 배포판으로, 늘 세 갈래를 함께 운영합니다. 공식 릴리스인 **stable**, 다음 stable을 준비하는 **testing**, 개발이 실제로 일어나는 **unstable**(별칭 sid)입니다. 일반 사용자에게 권하는 것은 stable이며, Debian LTS 프로젝트가 각 stable 릴리스의 지원 기간을 최소 5년까지 늘려 줍니다.

**Ubuntu**는 Canonical이 Debian을 바탕으로 만드는 배포판입니다. 6개월마다 새 버전이 나오고, 2년마다 나오는 **LTS(장기 지원)** 버전은 5년 동안 표준 보안 업데이트를 받습니다. Kubuntu, Xubuntu, Lubuntu처럼 데스크톱 환경만 바꾼 공식 플레이버(flavor)도 있습니다.

Ubuntu 위에 다시 만든 배포판도 많습니다. [Linux Mint](../../distros/linux-mint/), [Pop!\_OS](../../distros/pop-os/), [Zorin OS](../../distros/zorin-os/)가 대표적이고, Linux Mint는 Ubuntu 대신 Debian을 직접 바탕으로 한 LMDE도 따로 냅니다. 이 계열은 사용자가 가장 많아 자료를 찾기 쉽고, 상용 프로그램 중에도 `.deb` 패키지를 제공하는 것이 많습니다.

### Fedora와 Red Hat 계열

**Fedora**는 Red Hat이 후원하는 커뮤니티 배포판입니다. 대략 6개월마다 새 버전이 나오고 각 버전은 약 13개월 동안 업데이트됩니다. 새 기술을 빨리 받아들이는 편이라 최신 데스크톱을 깔끔하게 쓰고 싶은 사람에게 잘 맞습니다.

기업용 쪽은 흐름이 이어집니다. Fedora에서 다듬어진 기술이 **CentOS Stream**을 거쳐 **Red Hat Enterprise Linux(RHEL)** 로 들어갑니다. CentOS Stream은 RHEL보다 한발 앞서 계속 업데이트되는 "중간 단계" 배포판입니다. RHEL은 한 버전을 10년 주기로 지원합니다. **AlmaLinux**와 **Rocky Linux**는 RHEL과 바이너리 호환되는 무료 커뮤니티 배포판으로, 2020년 말 Red Hat이 기존 CentOS Linux를 끝내고 CentOS Stream으로 전환한다고 발표한 뒤 그 자리를 채우려고 생겨났습니다. 서버 용도로 많이 쓰입니다.

### Arch 계열

**Arch Linux**는 독립적으로 개발되는 x86-64용 배포판으로, 롤링 릴리스 방식으로 대부분의 소프트웨어를 최신 안정 버전으로 유지합니다. 원래 개발자(업스트림)가 내놓은 그대로를 최소한으로만 고쳐서 제공하고, 시스템을 어떻게 꾸밀지는 사용자에게 맡깁니다. 커뮤니티가 함께 관리하는 **AUR(Arch User Repository)** 과 내용이 풍부한 **Arch Wiki**가 큰 장점입니다.

Arch를 더 쉽게 쓰도록 만든 파생 배포판도 많습니다. **Manjaro**는 패키지를 자체적으로 시험한 뒤 단계적으로 내보내고, **EndeavourOS**는 Arch에 가까운 터미널 중심 환경을 쉽게 설치할 수 있게 해 주고, **CachyOS**는 최신 CPU에 맞춰 최적화한 패키지와 커널로 성능에 초점을 둡니다.

<Callout type="note" title="파생 배포판의 질문은 그 배포판 커뮤니티에">
  Arch 커뮤니티와 개발자는 Arch 기반 배포판을 지원하지 않습니다. Manjaro나 EndeavourOS에서 생긴 문제는 해당 배포판의 포럼에 먼저 물어보세요. 다른 계열도 마찬가지입니다.
</Callout>

### SUSE 계열

**openSUSE Tumbleweed**는 롤링 릴리스 배포판으로, 패키지 하나하나뿐 아니라 여러 패키지 묶음을 서로 맞물려 시험한 뒤 내보냅니다. 명령 하나로 이전 스냅숏으로 되돌릴 수 있는 것도 특징입니다. **openSUSE Leap**은 기업용 **SUSE Linux Enterprise(SLE)** 의 소스에 커뮤니티 개발 성과를 합친 정기 릴리스로, 안정성을 중시합니다.

### 독립 배포판

어느 계열에도 속하지 않고 자기만의 방식을 고수하는 배포판도 있습니다.

- **Gentoo**: Portage라는 도구로 소프트웨어를 내 컴퓨터에 맞게 직접 빌드해 설치합니다. 스스로를 "메타 배포판"이라 부를 만큼 설정 폭이 넓습니다.
- **Alpine Linux**: musl libc와 BusyBox를 바탕으로 한 아주 작은 배포판입니다. 패키지 관리자 apk와 OpenRC를 쓰며, 작아서 컨테이너 이미지로도 많이 쓰입니다.
- **Void Linux**: 자원봉사자가 만드는 독립 롤링 배포판으로, XBPS 패키지 관리자와 runit init을 씁니다. glibc판과 musl판을 모두 제공합니다.
- **NixOS**: 시스템 전체를 설정 파일 하나에 선언하듯 적어 두면 그대로 만들어 줍니다. 업데이트가 다른 패키지를 망가뜨리지 않도록 설계했고, 이전 상태로 쉽게 되돌릴 수 있습니다.
- **Slackware**: 오랜 역사를 지닌 배포판으로, 단순하고 전통적인 유닉스 방식을 지킵니다.

## 릴리스 모델

배포판을 고를 때 계열만큼 중요한 것이 **업데이트를 어떤 리듬으로 받느냐**입니다.

| 모델 | 방식 | 좋은 점 | 신경 쓸 점 | 예 |
|---|---|---|---|---|
| 정기 릴리스(fixed) | 정해진 주기로 새 버전을 내고, 버전 안에서는 주로 보안·버그 수정만 합니다 | 예측 가능하고 안정적 | 지원이 끝나기 전에 다음 버전으로 올려야 합니다 | Fedora, Ubuntu 일반 버전, Debian stable |
| 장기 지원(LTS) | 정기 릴리스 중 일부를 수년간 지원합니다 | 오래 손대지 않아도 됩니다 | 새 하드웨어·새 기능 반영이 느립니다 | Ubuntu LTS, RHEL, AlmaLinux, Rocky Linux |
| 롤링(rolling) | 버전 구분 없이 패키지를 계속 최신으로 올립니다 | 항상 최신 커널·드라이버·앱 | 자주 업데이트하고 변화에 대응해야 합니다 | Arch Linux, openSUSE Tumbleweed, Void Linux |
| 세미 롤링(semi-rolling) | 기반은 고정하거나 늦게 따라가고, 일부만 계속 최신으로 올립니다 | 안정성과 최신성의 절충 | 배포판마다 방식이 제각각입니다 | Manjaro, KDE neon |

세미 롤링은 정해진 정의가 있는 용어가 아니라서 배포판마다 뜻이 조금씩 다릅니다. 예를 들어 Manjaro는 Arch의 패키지를 바로 내보내지 않고 시험을 거친 뒤 단계적으로 내보내고, KDE neon은 Ubuntu LTS를 바탕으로 KDE 소프트웨어만 롤링 방식으로 계속 업데이트합니다.

<Callout type="tip" title="롤링이 곧 불안정하다는 뜻은 아닙니다">
  롤링 배포판도 패키지를 시험한 뒤 내보냅니다. 다만 변화가 끊임없이 들어오므로, 몇 달씩 업데이트를 미루기보다 자주 조금씩 업데이트하고 배포판의 공지(뉴스)를 확인하는 습관이 필요합니다.
</Callout>

카탈로그에서 [정기 릴리스](../../distros/?model=fixed), [장기 지원](../../distros/?model=lts), [롤링](../../distros/?model=rolling), [세미 롤링](../../distros/?model=semi-rolling) 배포판만 골라 볼 수 있습니다.

## 불변(immutable)·아토믹(atomic) 배포판

최근 늘어나는 유형으로, 시스템 파일을 **읽기 전용**으로 두고 운영체제 전체를 하나의 이미지처럼 통째로 업데이트합니다. 업데이트는 새 시스템 이미지를 옆에 준비해 두었다가 다시 시작할 때 바꾸는 방식이라, 업데이트 도중 전원이 꺼져도 시스템이 반쯤 망가지는 일이 없고 문제가 생기면 이전 이미지로 되돌리면 됩니다.

| | 일반 배포판 | 불변·아토믹 배포판 |
|---|---|---|
| 시스템 파일 | 관리자 권한으로 직접 수정 | 읽기 전용(설정 `/etc`와 데이터 `/var`만 쓰기 가능) |
| 업데이트 | 패키지를 하나씩 교체 | 이미지를 통째로 교체, 재부팅 후 적용 |
| 되돌리기 | 별도 스냅숏 도구 필요 | 이전 이미지로 바로 부팅 |
| 앱 설치 | 배포판 패키지 | Flatpak, Toolbx 같은 컨테이너, 꼭 필요할 때만 패키지 레이어링 |

대표적인 예는 다음과 같습니다.

- **Fedora Atomic Desktops**: GNOME을 쓰는 Silverblue, KDE Plasma를 쓰는 Kinoite를 비롯해 Sway·Budgie·COSMIC 버전이 있습니다.
- **Universal Blue 계열**: Fedora Atomic Desktops를 바탕으로 하드웨어 지원과 편의 기능을 더해 컨테이너 이미지 방식으로 만든 시스템들로, 게임용 [Bazzite](../../distros/bazzite/)가 유명합니다.
- **openSUSE MicroOS**: 읽기 전용 Btrfs 루트 위에서 트랜잭션 방식으로 업데이트합니다.
- **NixOS**: 엄밀히는 방식이 다르지만, 선언적 설정과 손쉬운 되돌리기로 비슷한 장점을 얻습니다.
- **Ubuntu Core**: 기기·IoT용 불변 배포판으로, 커널과 OS, 앱을 서로 분리해 따로 업데이트합니다.

운영체제 이미지를 일반 컨테이너 이미지처럼 만들고 배포하는 **부팅 가능한 컨테이너(bootc)** 도 같은 흐름에 있습니다. Fedora Atomic에서는 다음과 같은 명령을 씁니다.

```bash
rpm-ostree status      # 현재 이미지와 이전 이미지 확인
rpm-ostree upgrade     # 새 이미지 받기 (다시 시작하면 적용)
rpm-ostree rollback    # 이전 이미지로 되돌리기
```

<Callout type="note" title="불변 배포판이 맞지 않는 경우">
  시스템 깊숙한 곳을 자주 고치거나, 특정 드라이버와 커널 모듈을 직접 빌드해야 하거나, 설치 스크립트가 시스템 디렉터리에 파일을 쓰는 프로그램을 많이 쓴다면 일반 배포판이 더 편할 수 있습니다.
</Callout>

## 나에게 맞는 배포판 고르기

"가장 좋은 배포판"은 없고, 내 상황에 맞는 배포판이 있을 뿐입니다. 다음 질문에 답해 보면 후보가 금방 좁혀집니다.

- **무엇에 쓰나요?** 일상 사무, 게임, 개발, 서버, 오래된 PC 살리기에 따라 출발점이 다릅니다.
- **얼마나 손을 대고 싶나요?** 설치하자마자 쓰고 싶다면 입문자용 배포판이, 직접 하나씩 구성하고 싶다면 Arch나 Gentoo가 맞습니다.
- **안정과 최신 중 무엇이 중요한가요?** 오래 신경 쓰지 않으려면 LTS, 새 하드웨어나 최신 앱이 중요하면 Fedora나 롤링 배포판이 낫습니다.
- **어떤 화면이 편한가요?** 첫인상은 배포판보다 [데스크톱 환경](../desktop-environments/)이 좌우합니다.

| 상황 | 먼저 살펴볼 만한 배포판 |
|---|---|
| 리눅스가 처음이고 Windows와 비슷한 화면이 편함 | [Linux Mint](../../distros/linux-mint/), [Zorin OS](../../distros/zorin-os/), [Kubuntu](../../distros/kubuntu/) |
| 최신 소프트웨어와 깔끔한 기본 데스크톱 | [Fedora](../../distros/fedora/), [Ubuntu](../../distros/ubuntu/) |
| 게임 | [Bazzite](../../distros/bazzite/), [Pop!\_OS](../../distros/pop-os/) — [게임](../gaming/) 장 참고 |
| 오래되거나 사양이 낮은 PC | [Xubuntu](../../distros/xubuntu/), [Linux Lite](../../distros/linux-lite/), [MX Linux](../../distros/mx-linux/) |
| 서버, 오래 켜 두는 시스템 | [Debian](../../distros/debian/), [AlmaLinux](../../distros/almalinux/), [Rocky Linux](../../distros/rocky-linux/) |
| 리눅스를 깊이 배우고 직접 구성 | [Arch Linux](../../distros/arch/), [NixOS](../../distros/nixos/), [Gentoo](../../distros/gentoo/) |

Linuxhub에서는 다음 순서로 고르는 것을 권합니다.

<Steps>

1. [배포판 찾기](../../finder/)에서 몇 가지 질문에 답해 후보를 2~3개로 좁힙니다.
2. [배포판 목록](../../distros/)에서 용도, 계열, 데스크톱 환경, 릴리스 모델로 걸러 보고, 마음에 드는 후보를 [비교](../../compare/)합니다.
3. 후보를 라이브 USB로 부팅해 직접 써 봅니다. 설치하지 않아도 화면과 Wi-Fi, 소리가 잘 되는지 확인할 수 있습니다.
4. 마음을 정했다면 [설치 준비](../installation-prep/)를 읽고 설치합니다.

</Steps>

<Callout type="tip" title="처음 고른 배포판이 마지막일 필요는 없습니다">
  배포판을 바꿔도 리눅스 지식은 대부분 그대로 쓸 수 있습니다. 같은 계열 안에서는 명령어까지 같습니다. 개인 파일을 별도로 백업해 두는 습관만 있으면 부담 없이 다른 배포판을 시험해 볼 수 있습니다.
</Callout>
